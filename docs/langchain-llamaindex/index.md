# LangChain & LlamaIndex 応用アプリケーションアーキテクチャ——AIエージェントとRAGの実装パターン

LLMアプリケーションのプロトタイプは、いまや数十行で書ける。難しいのはその先である。社内の数万件の文書に対して「だいたい合っている」ではなく「根拠付きで正しい」と言える検索を作る。ツールを呼ぶエージェントが、失敗したときに黙って嘘をつくのではなく、失敗を検知して立て直す。処理の途中に人間の承認を挟み、中断と再開に耐える。本書が扱うのは、この「デモから本番までの距離」を埋める設計である。

## この本の立ち位置

LangChainもLlamaIndexも、便利な関数の詰め合わせではなく、それぞれ明確な設計思想を持ったフレームワークである。その思想を理解せずにチュートリアルのコードをつなぎ合わせると、動くには動くが、精度が出ないときにどこを触ればよいのか分からないアプリケーションができあがる。

本書はラッパーの使い方を一覧する本ではない。`RetrievalQA` の内側で何が起きているのか、`create_agent` は結局どんなループを回しているのか、LCELの `|` は何を組み立てているのか——抽象化の下で動いている仕組みを開けて確かめ、そのうえで、どこを自前の部品に差し替えるべきかを判断できるようになることを目標にする。

> フレームワークは、正しく使えば設計の共通言語になり、中身を知らずに使えばデバッグ不能なブラックボックスになる。

## 対象読者

- LLMを使ったエンタープライズ向けのソリューションを実装している開発者・アーキテクト
- PythonとWeb APIの実装経験があり、LangChainやLlamaIndexのチュートリアルは一通り触ったことがある人
- ナイーブなRAGを作ってはみたものの、精度が頭打ちになって次の一手を探している人
- エージェントを本番に載せるにあたって、暴走・停止条件・人間の承認をどう設計するか悩んでいる人

Transformerやベクトル検索そのものの入門的な解説は、[生成AI/LLMアプリケーション開発](/llm-app-development/)の目次案に譲り、本書では前提知識として扱う。

## コードの前提

本書のコードはPython 3.12で書き、次のバージョンを前提としている。LangChainとLlamaIndexはいずれも変化の速いライブラリであり、マイナーバージョンの違いでインポートパスが変わることも珍しくない。掲載したコードは仕組みを説明するための骨格であり、そのまま動く完全なスクリプトではない箇所がある。

| ライブラリ | 想定バージョン |
| --- | --- |
| `langchain-core` / `langchain` | 1.0系 |
| `langgraph` | 1.0系 |
| `llama-index-core` | 0.14系 |
| `pydantic` | 2系 |
