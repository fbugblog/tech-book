# dbtによるモダンデータエンジニアリング — 変換パイプラインのコード化と設計パターン

データ変換のコードは、いつのまにか壊れる。壊れ方も決まっている。誰かが手で直したビューが本番に残り、似たようなロジックが五つのクエリに散らばり、数字が合わないという問い合わせが来て初めて、三か月前に上流のカラムが増えていたことに気づく。SQLの書き方が下手だったからではない。SQLにソフトウェアエンジニアリングの作法が入っていなかったからである。

本書は、dbt（data build tool）を軸に、SQL中心の変換処理へバージョン管理・モジュール化・テスト・CI/CDを持ち込むための実務書である。文法の網羅は目的にしていない。運用が破綻しないパイプラインを組むための、設計の型と判断基準を扱う。

## 対象読者

- データ変換パイプラインを実際に構築・保守しているデータエンジニア
- 顧客先でデータ基盤を立ち上げ、引き継げる形で残す必要があるコンサルタント・FDE
- SQLは書けるが、テストやCIといったソフトウェア開発の作法をデータ基盤側に持ち込めていない人

SQLの基本構文とGitの基本操作は前提にする。特定のデータウェアハウス製品の知識は前提にしない。
