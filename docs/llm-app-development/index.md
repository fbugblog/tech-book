# 生成AI/LLMアプリケーション開発 — 深掘り本 目次案

LLMアプリケーション開発を、基礎→応用→最前線の三部構成・全30章で扱う本の章立てである。

構成にあたって二つの現場を意識した。一つは、顧客先で素早く動くものを作り切る実務。もう一つは、金融機関のオンラインバンキングのように、セキュリティとガバナンスの制約が最初から設計に食い込んでくる領域である。「動くものを速く作る」と「本番で預けられる形にする」の両方を扱わないと、この分野の本は実務の役に立たない、という判断から章を組んだ。

::: tip この記事の位置づけ
現在は章立てのみを公開している。本文は第1章から順に書き足していく予定である。
:::

## 第I部：基礎編（第1〜10章）——LLMアプリケーションの土台を固める

1. LLMアプリケーションとは何か——「チャットボット」から「業務に組み込まれるシステム」への転換
2. Transformerとトークン化のおさらい——なぜLLMは「次の単語」しか予測しないのに賢く見えるのか
3. 主要LLM API徹底比較——Claude・GPT・Gemini・Command、それぞれの強みと使い分け
4. プロンプトエンジニアリングの型——Few-shot、Chain-of-Thought、構造化出力（JSON Mode）の実践
5. Embeddingsとベクトル空間——「意味の近さ」を数値化する仕組み
6. ベクトルDB入門——Pinecone・Milvus・pgvector・S3 Vectors、どれを選ぶか
7. RAGの基本構造——Retriever・Chunking・Rerankerの3層モデル
8. LLM API×バックエンド設計——FastAPIでLLM呼び出しをラップする定石パターン
9. コストとレイテンシの基礎設計——トークン課金モデルとキャッシュ戦略
10. LLMアプリのセキュリティ基礎——プロンプトインジェクション、データ漏洩、金融データを扱う際の勘所

## 第II部：応用編（第11〜20章）——実務で動くシステムを作る

11. RAGを「壊れない」設計にする——チャンク戦略とオーバーラップ設計の実践
12. ハイブリッド検索とリランキング——Cohere Rerank・Jina Rerankerで精度を底上げする
13. RAG評価の実務——RAGAS指標（Context Precision/Recall、Faithfulness）で「測って直す」
14. AIエージェントとは何か——ツール利用・環境観察・自律判断という3要素
15. エージェントフレームワーク実践比較——LangGraph・CrewAI・AutoGen、PoCと本番での使い分け
16. Model Context Protocol（MCP）を理解する——エージェントと社内システムをつなぐ標準プロトコル
17. マルチエージェント・オーケストレーション——専門AIチームによる分業設計とA2A連携
18. Streamlit/Gradioで「その場でデモ」を作る——高速プロトタイピングの型
19. 金融ドメイン特化のLLMアプリ事例——不正検知支援、KYC文書処理、コールセンターAI要約
20. LLM Observability——OpenTelemetryによるトレース・コスト・ハルシネーション監視の実装

## 第III部：最前線・展望編（第21〜30章）——2026年の最先端と今後

21. Agentic RAG——検索を「一発で終わらせない」自律的な情報収集パターン
22. GraphRAGの実力——ナレッジグラフを組み込んだRAGの次世代形
23. コーディングエージェントの内側——リポジトリ横断推論とagentic codingの仕組み
24. ローカルLLMという選択肢——Llama 4、Qwen3系、Gemma系とハイブリッド運用の実際
25. マルチモーダルLLMアプリ——文書画像・音声を扱う実装パターン
26. エージェントの暴走をどう止めるか——停止条件・人間承認フロー・ゼロトラスト設計
27. 金融機関特有のAIガバナンス——説明可能性、監査ログ、当局対応という制約下での実装
28. LLMOpsの進化——AgentOpsへの統合と継続的評価サイクル
29. エンタープライズAI導入の失敗パターン集——PoCから本番化で躓く典型ケースとその回避策
30. AIエージェント時代の開発者の役割——顧客の業務にどこまで踏み込むべきか、今後の展望

## この章立てについて

特定パートを厚くする（第II部の金融特化事例を増やす、MCP／エージェント設計をさらに深掘りする）、逆に薄くするといった調整は、執筆を進めながら随時行う。
