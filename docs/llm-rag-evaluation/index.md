# LLM / RAGシステムの評価と品質保証

デモが動いた翌日に、必ず同じ質問が来る。これ、本番に出して大丈夫なのか。

この問いに「たぶん大丈夫だと思う」以外の答えを返せるようにするのが本書の目的である。非決定的なAIの出力を定量的なメトリクスに落とし、回帰テストとして自動実行し、本番の挙動を監視して次の改善につなげる。その一連のパイプラインを、Ragas・DeepEval・LLMOpsツール群を軸に組み立てていく。

## 対象読者

- RAGやLLMエージェントのPoCを動かしたあと、本番運用の品質基準づくりで止まっているエンジニア
- プロンプトやモデルを差し替えるたびに「良くなったのか悪くなったのか」を説明できずにいるチーム
- LLM機能のリリース可否を判断する立場にあり、その判断材料を数字で欲しいプロダクトマネージャー

LLMやRAGの基本構造（Embedding、ベクトル検索、プロンプト設計）は前提にしている。評価と品質保証の側だけを、実装できる粒度まで掘り下げる。

## 検証環境

本書のコードは次のバージョンで動作を確認している。

| 対象 | バージョン |
| --- | --- |
| Python | 3.11 |
| ragas | 0.2系 |
| deepeval | 2系 |
| pytest | 8系 |
| 評価器として使うモデル | Claude Opus 5（`claude-opus-5`） |

評価フレームワークはAPIの変更が速い領域である。インポートパスやクラス名が本書と食い違う場合は、まず各プロジェクトの公式ドキュメントで現行のシグネチャを確認してほしい。本書が伝えたいのは個々の関数名ではなく、何を測り、どこに閾値を置き、どう自動化するかという設計の骨格である。
